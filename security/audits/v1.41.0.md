# Gleam v1.41.0 security audit

## Scope

Diff: `c888d26..e021d48`. This release ships the fixes for the private advisories triaged after v1.40.0 (#141), the untrusted-text change in #142, and the surface additions in #143.

Surface paths changed:

- `packages/runtime/src/handlers/approval.ts`:
  - A `signDataItem` approval now previews the one item it signs, with its target and any AO `Transfer` it carries (recipient, raw quantity, process id). Before, a single item showed no target (GHSA-9h5g).
  - Pending approvals are capped at 4 MiB in total and 2 MiB per origin, measured on the stored record. Gleam's own requests are kept out of the dApp pool (GHSA-6r3c).
  - Bytes are stored with `toStored`/`fromStored` in place of the tagged-binary codec.
  - A signing request is dropped with "The active wallet changed." if the wallet it was made for is no longer active when it is queued. `rejectSwitchedApprovals` rejects the ones still pending on a switch (GHSA-8382).
  - Grant writes go through one queue (`updateGrants`), so overlapping revokes can't restore each other's grants from a stale read (GHSA-8wmv).
  - A failed `present` drops the pending record instead of leaving it queued.
  - Approval requests carry the site's saved grant icon.
- `packages/runtime/src/create-runtime.ts`:
  - `connect` and `walletSwitch` events carry an address only to a secure origin whose grant can read it, and never a watch wallet's address. Before, they went to any granted origin (GHSA-3387).
  - Every path that changes the active wallet rejects that wallet's pending signing requests before it broadcasts.
  - An L1 transaction or data item that is a token transfer is previewed as that transfer, scaled only by the token's resolved metadata.
- `packages/app/src/approval/SigningApprovalScreen.tsx`, `AwaitingDeviceView.tsx`, `ApprovalRoot.tsx`: value-moving requests render in the shared `TransferReview` (every send in one list, fee and total labelled AR, the fee shown with no recipient: GHSA-p24r, GHSA-74qh). A token transfer always shows its process id and raw quantity (GHSA-29gg).
- `packages/app/src/approval/UntrustedText.tsx` (new): site-supplied text shows bidi, zero-width and control characters as `<U+XXXX>` in an isolated left-to-right run (GHSA-52m7). It is used by the signing previews, data item cards, the connect screen's app name and the add-token ticker and name.
- `packages/app/src/approval/ConnectionRequestScreen.tsx`, `AddTokenScreen.tsx`: site-chosen names through `UntrustedText`.
- `packages/app/src/approval/ScanAttestationScreen.tsx`: layout and copy.
- `packages/app/src/transfer-review/` and `packages/core/src/ao/transfer-message.ts` (new), `packages/core/src/ao/l1-transfer.ts`: the transfer review and the AO and L1 transfer readers that the approvals above use. They now decide what an approval shows, so they join the surface at tier 4 (F-11).
- `security/surface.txt`, `.github/CODEOWNERS`: the three paths above.
- `packages/app/src/i18n/messages/approval.ts`, `transfer-review.ts`, `points.ts`, `index.ts`: copy for the above in every language.

Other changes, outside the surface:

- Send and send-collectible screens use `TransferReview` for their own review step.
- Phone layout: text selection and the iOS callout are off for the whole tree, and stay on in fields.
- Token logos cached on the device by transaction id (`logo-cache.ts`).
- Points API: a snapshot credits a wallet from its last read when a read fails.
- `scripts/scan` test runs the CLI through `node --import tsx`.
- Versions: 1.41.0.

Run:

- `pnpm vitest run`: 4291 passed, 5 skipped.
- tsc on all eleven projects, eslint, `pnpm wxt:build`, `pnpm mobile:build`.

## Findings

| id   | severity | summary | status |
| ---- | -------- | ------- | ------ |
| F-1  | high   | A single `signDataItem` approval hid the item's target, so an AO `Transfer` to any process read as a plain message. The preview now shows the target and the decoded transfer. (GHSA-9h5g) | fixed |
| F-2  | medium | A token transfer's approval trusted the token's self-reported identity and metadata. It now always shows the process id and the raw quantity. (GHSA-29gg) | fixed |
| F-3  | medium | A signing request made before a wallet switch could be approved and signed by the newly active wallet. (GHSA-8382) | fixed |
| F-4  | medium | Overlapping grant revokes could restore a revoked grant from a stale read. (GHSA-8wmv) | fixed |
| F-5  | medium | Bidi and zero-width characters in previewed text could reorder or hide what was signed. (GHSA-52m7) | fixed |
| F-6  | medium | A transaction with no recipient showed no network fee. The fix also covers the request's origin header. (GHSA-74qh) | fixed |
| F-7  | medium | A site could fill `chrome.storage.session` with pending approvals. (GHSA-6r3c) | fixed |
| F-8  | low    | The fee and total on signing approvals had no AR unit. (GHSA-p24r) | fixed |
| F-9  | low    | `connect` and `walletSwitch` events sent the active address to origins whose grant couldn't read it. (GHSA-3387) | fixed |
| F-10 | low    | The connect screen's app name and the add-token ticker and name rendered as plain text, outside `UntrustedText`. | fixed |
| F-11 | low    | The transfer review and the AO and L1 transfer readers decide what signing approvals show, but they were not in `security/surface.txt`, so the release gate didn't re-audit changes to them. They are now in the surface and CODEOWNERS. | fixed |
| F-12 | info   | `fromStored` turns any plain object shaped `{ __gleamStored, base64 }` into bytes. A site can't reach it: every provider-params reader rebuilds the input field by field, so no site object is stored as is. | accepted |
