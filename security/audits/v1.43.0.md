# Gleam v1.43.0 security audit

## Scope

Diff: `5013639..62cde9d`. This release adds AO peer failover and on-chain peer discovery (#153), shows each batch transfer's process and raw units on its card (#155), splits the send fee quote from the recipient checks (#154), keeps a dusted address first time (#161), shows AR and AO logos on token details (#162), and bumps dependencies and pinned actions.

Surface paths changed:

- `packages/runtime/src/handlers/transfer.ts`, `packages/messaging/src/protocol.ts`: `estimateTransfer` and `estimateCollectibleSend` return only the fee (`TransferFeeQuote`). The first-time and lookalike checks come from `assessRecipient`, which the send and collectible review screens call on their own. Send stays disabled while that check runs, so a warning can't arrive after the tap (F-4).
- `packages/runtime/src/create-runtime.ts`: registers the daily peer discovery alarm, and `setNetworkSettings` goes through `saveNetworkSettings`, which remembers a community or discovered peer the user removed so the merge doesn't add it back.
- `packages/app/src/transfer-review/TransferReview.tsx`: a token transfer's card shows its process and raw units, since the ticker and scale come from untrusted metadata (F-2).
- `packages/app/src/approval/ScanAttestationScreen.tsx`: Join Points uses `mutateAsync`, so a click before the mutation observer subscribes still moves on to the review. No change to what is signed.
- `.github/workflows/*.yml`: `step-security/harden-runner` 2.22.2 → 2.22.3 and `zizmorcore/zizmor-action` 0.8.0 → 0.8.1, both pinned by sha.
- `apps/mobile/plugins/dapp-view/package.json`, `pnpm-lock.yaml`: Capacitor 8.5.3 → 8.6.0, `@dha-team/arbundles` 1.1.0 → 1.2.0, TanStack Query 5.105.1, `hono` 4.13.16 and dev-only bumps (#160). The arbundles change replaces axios with `fetch` in the Node-only `FileDataItem.sendToBundler`, which Gleam doesn't use.
- `packages/app/src/i18n/messages/main-screen.ts`, `points.ts`, `send.ts`: copy for the activity sheet, recent Points earnings and the batch card rows.

Outside the surface, read for this audit:

- `packages/core/src/ao/peer-discovery.ts`, `peer-failover.ts`, `packages/runtime/src/peers.ts`, `handlers/reads.ts`: discovery reads `Type: Location|Scheduler-Location` and `type: location` records through gateway GraphQL. It keeps only bare public https origins (no credentials, path, query, private IPv4, IPv6 literal, `localhost` or tunnel hosts) that answer `/~meta@1.0/info/address`. Discovered and community peers are merged into the settings on read, never written back, and stay out of `host_permissions`. Token balance and collectible reads fail over to up to three peers on a network error, timeout or 5xx (F-3).
- `packages/core/src/recipients/assess.ts`: `firstTime` holds until the wallet has sent to the address, so an incoming dust transfer no longer clears it (F-1).

## Notes

No open critical or high finding.

F-3 is accepted because failover only covers reads that are display or pre-checks: a wrong balance can misstate the balance and balance-after lines or block a send, and a send above the real balance is refused by the token. Before this release, reads used only the active peer, so a down peer failed them outright.

Known limitations: added "Failover peers are not vetted" (F-3). The Network section now names the community and discovered peers.
