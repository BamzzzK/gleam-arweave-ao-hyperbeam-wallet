# Gleam v1.42.0 security audit

## Scope

Diff: `e021d48..5013639`. This release ships the fixes for the private advisories triaged after v1.41.0 (#146), the security-surface additions in #145, and a send-review layout change.

Surface paths changed:

- `packages/core/src/ao/l1-transfer.ts`, `collectible-transfer.ts`: `readL1TokenTransfer` matches `action`, `recipient` and `quantity` by name, case-insensitively and in any order, each exactly once, with other tags allowed, since the scheduler and HyperBEAM's `dev_token` read them that way. A transaction with an `action=transfer` tag that doesn't read cleanly (a repeated name, AR value, data, a bad recipient or quantity) reads as `unreadable` (GHSA-6584).
- `packages/core/src/ao/transfer-message.ts`: `readAoTransferMessage` keeps its exact-case read, which legacy aos matches, and returns `unreadable` for a data item with an `action=transfer` tag in any case that has no clean read, including a name given twice in any case.
- `packages/core/src/models/approval.ts`: `unreadableTokenTransfer` on the signing preview, its items, and the `transaction` and `dataItem` device summaries.
- `packages/runtime/src/create-runtime.ts`: an unreadable L1 transfer or data item is previewed as the plain request with the flag set, instead of as a zero-AR send or a plain item.
- `packages/runtime/src/handlers/approval.ts`:
  - The device summary and data-item previews carry the unreadable flag.
  - `revokeGrant` rejects the origin's pending requests and closes their windows. A pending `connect` stays, since approving it is a fresh grant. `resolveApproval` and `submitDeviceSignature` re-check the grant before signing, and after for result-only kinds (`sign`, `signDataItem`, `batchSignDataItem`, `signMessage`, `encrypt`, `decrypt`), whose result is withheld if the grant lapsed. Kinds that post keep their real outcome, so a site doesn't retry and send twice (GHSA-xw9m).
  - `storedSize` counts strings and keys in UTF-8 bytes, as `chrome.storage.session` charges them (GHSA-4fx3).
- `packages/app/src/transfer-review/model.ts`, `TransferReview.tsx`: the unreadable warning (red primary action, Details and tags open). The balance-after line is built from parts and renders each ticker through `UntrustedText` (GHSA-9v85). Glyph initials drop hidden characters. The collectible hero's image alt is empty, since the name shows escaped below it.
- `packages/app/src/approval/AwaitingDeviceView.tsx`: the unreadable warning on the device step. The amount row's ticker and the message row render through `UntrustedText`.
- `packages/app/src/approval/SigningApprovalScreen.tsx`: the unreadable warning and red Sign button on the generic data-item path.
- `packages/ui/src/components/wallet/RecipientWarning.tsx` (`extraReasons` list), `CollectibleThumbnail.tsx` (`decorative`).
- `security/surface.txt`, `.github/CODEOWNERS`: 19 paths added (#145), among them `method-permissions.ts`, `method-privileges.ts`, `capabilities.ts`, `csp.ts`, the Ledger and Keystone panels, `site-wallet.ts` and `announcements.ts`.
- `packages/app/src/i18n/messages/*`: the unreadable-transfer warning in every language; "scan" in place of "review" for the community scan; plainer wording for approval and permission copy.
- `apps/site/scan.html`, `review-results.html`, `review-results.js`, `scan-lib.js`, `attest.html`, `security.html`, `points.html`: copy only ("scan" for the community scan).
- `packages/app/src/transfer-review/model.ts`, `TransferReview.tsx` (layout): the network fee shows in AR to three significant digits, rounded up so it never reads lower than what is paid, with its value in the display currency when AR is priced. A nonzero value below the currency's smallest step reads "< $0.01" instead of "≈ $0.00". The from/to connector is an arrow and the avatars are 36px (F-7).

Run:

- `pnpm vitest run`: 4348 passed, 5 skipped.
- tsc on all eleven projects, eslint, `pnpm wxt:build`, `pnpm mobile:build`.
- Manual check in Chrome: reordered, recased and extra-tag L1 transfers; unreadable L1 transfers and data items; revoke and `disconnect()` while a request is pending.
