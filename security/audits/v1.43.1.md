# Gleam v1.43.1 security audit

## Scope

Diff: `62cde9d..7349f11`. This release ships the fixes for the private advisories triaged after v1.43.0, and the surface additions in #164. v1.43.0 was tagged but never signed or published to a store, so this release replaces it.

Surface paths changed:

- `packages/core/src/ao/l1-transfer.ts`: `readL1TokenTransfer` reads any `Assign-To` tag, in any case, as `unreadable`. The scheduler hands the transaction to each process it names, so each would run the same transfer of its own token (GHSA-5vc6). Collectible sends read through the same function.
- `packages/runtime/src/handlers/approval.ts`: the connect preview's `appInfo.logo` goes through `safeSiteIconUrl` (https or a `data:image/*` URL), as the icon kept on the grant already did, so the approval window makes no plaintext fetch (GHSA-v5v3).
- `packages/runtime/src/peers.ts`: `saveNetworkSettings` counts the stored peer list as well as the community and discovered lists when recording removals, so a removed peer stays removed after discovery drops it and finds it again (GHSA-j6pp).
- `pnpm-workspace.yaml`, `pnpm-lock.yaml`: `node-forge` 1.4.2 → 1.4.3. Gleam uses only `pki.rsa.generateKeyPair`, `hmac` and `util` (`core/keys/mnemonic-jwk.ts`), none of which the 1.4.3 advisories touch (GHSA-vrx8).
- `security/surface.txt`, `.github/CODEOWNERS`: `peer-discovery.ts`, `peer-failover.ts`, `peers.ts`, `network.ts`, `protocol.ts`, `recipients/assess.ts` and `handlers/reads.ts` (#164), and `arweave/first-run-gateway.ts` and `arweave/graphql.ts` (GHSA-pwjh).
- `packages/core/src/recipients/assess.ts`: doc comment only.

Run:

- `pnpm vitest run`: 4411 passed, 5 skipped.
- tsc on all eleven projects, eslint, `pnpm wxt:build`, `pnpm mobile:build`.

## Notes

No open critical or high finding.

Already fixed: GHSA-vvqv (a `dispatch` over 100 KB with AO Transfer tags previewing as 0 AR) was reported against v1.41.0. Since v1.42.0 F-1 (GHSA-6584), an `action=transfer` tag in any case on a transaction with data reads as unreadable, so the preview shows the plain request with the warning and Details open. A test now pins that case.

Not a vulnerability: GHSA-rggv (`isTokenAdded` answers a connected site without a token permission). It matches Wander and is now a By design entry.

F-6 is accepted because codes travel in links by design, the attacker gains nothing, and Phase 2 removes the invite gate.

Known limitations: added the invite-seat entry under Points and scans (F-6). By design: added the `isTokenAdded` entry.
