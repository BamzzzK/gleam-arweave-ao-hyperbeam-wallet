# Gleam v1.38.0 security audit

## Scope

Diff: `1ce235d..78a3d3b`.

Surface paths changed:

- `packages/core/src/keys/mnemonic.ts`: BIP-39 phrase handling, English wordlist only. `checkMnemonic` checks wordlist membership, word count and the checksum. `mnemonicToSeed` is PBKDF2-HMAC-SHA512 in WebCrypto, with no passphrase. The entropy, bit and password buffers are zeroed after use. Gleam never generates or stores a phrase.
- `packages/core/src/keys/mnemonic-jwk.ts`: derives the RSA-4096 key that Wander and arweave.app derive from a seed. It uses an HMAC-DRBG (SHA-256) seeded only with the BIP-39 seed and feeds it to forge's PRIMEINC key generation as the only randomness. It refuses to run where `Worker` exists, because forge would split the prime search across racing workers and the key would vary.
- `packages/core/src/keys/bip39-wordlist.ts`: the wordlist, pinned to the upstream file's SHA-256 by `bip39-wordlist.keys.test.ts`.
- `packages/core/src/keys/mnemonic-vectors.ts` and the `*.keys.test.ts` files: BIP-39 reference vectors, plus phrases with the address and keyfile hash that Wander produced. A drift in derivation fails the build.
- `pnpm-workspace.yaml`, `pnpm-lock.yaml`: `node-forge` is pinned to exactly 1.4.2 (it was `^1.4.2`) and becomes a direct dependency of `@gleam/core`. Also adds `@types/node-forge` (dev).
- `packages/app/src/screens/onboarding/src/OnboardingView.tsx`: an `import-phrase` step. Its keyfile goes to the same password step and `importWallet` call as a keyfile import, so the background validates it the same way.
- `packages/app/src/i18n/messages/onboarding.ts`, `home-screen.ts`, `settings-home.ts`, `language.ts`, `index.ts`: phrase-import labels, and settings and home-screen labels moved or trimmed. No approval or recovery text changed.

Other changes, outside the surface:

- `ImportPhrase.tsx`, `phrase-grid.ts`, `phrase-key.ts`, `phrase-key.worker.ts`: the phrase grid and the worker that derives the key. Each derivation gets its own worker, which is shut down on reply or cancel. The worker accepts only messages from the page that created it, and only 12 to 24 lowercase words.
- The Settings home-screen layout moved a level down. Option lists are simpler.
- `wallet-lifecycle.*.test.ts` import a real RSA key.
- Versions: 1.38.0.

Run:

- `pnpm vitest run`: 4201 passed, 5 skipped. One test failed on the first of three runs and passed on the other two; the cut-off log didn't name it.
- tsc on all eleven projects, `pnpm wxt:build`, `pnpm mobile:build`, `pnpm audit --prod`.

## Findings

| id  | severity | summary | status |
| --- | -------- | ------- | ------ |
| F-1 | info | Miller-Rabin witnesses inside forge come from `Math.random`, as they do in Wander. They affect only the primality test, not the primes chosen, so a phrase derives the same key except with negligible probability. | accepted |
| F-2 | info | The phrase sits in React state and the worker's memory as JS strings, which can't be zeroed. The cells are cleared after derivation, the worker is shut down, and the phrase never crosses to the background or into storage. | accepted |
| F-3 | info | A phrase pasted from the clipboard stays there. Gleam can't clear another app's clipboard reliably, so after a paste the screen tells the user to copy something else. | accepted |
| F-4 | low | One low advisory from `pnpm audit --prod` (`elliptic`, no patched version, through the extension's node polyfills), unchanged from v1.32.1. | accepted |
| F-5 | info | Findings accepted in v1.37.0 are unchanged: F-1 to F-3. | accepted |

Severity: critical, high, medium, low, info. Status: fixed, accepted, open.
An open critical or high finding blocks the release.

## Notes

No critical or high finding.

Recovery-phrase import is the main surface change. Derivation stays in core with WebCrypto and one pinned dependency, checked against vectors from Wander. The result enters the vault only through the existing keyfile import path. No signing, approval, session or vault code changed.

Manual check in Chrome, unpacked: import a 12-word phrase from Wander and confirm the address matches, cancel during derivation, and check that a phrase with one wrong word is refused at the checksum.
