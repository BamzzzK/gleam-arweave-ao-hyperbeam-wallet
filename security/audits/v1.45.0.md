# Gleam v1.45.0 security audit

## Scope

Diff: `8a416ee..4f02d27`. The release carries both hardening rounds (#177, #201) and their follow-ups (#203), fixes for three low advisories (#187, and the provider-event fix in #177), two hardening fixes (#195, #196), a user-chosen bundler for dApp dispatches (#185), activity rows for uploads and swap orders (#207), and scan-reward changes outside the wallet.

Surface paths changed, by theme:

- **Signing check.** `runtime/src/handlers/prepared-check.ts` (new) reads prepared bytes back against the approved request. `handlers/transfer.ts` now builds a keyfile send with the same `prepareDeviceTransfer` a hardware wallet uses, runs `assertTransferMatches` (recipient, amount, token, fee, collectible), and only then signs; the one-step `submitTransfer` signers in `core/arweave/transfer.ts` and `core/ao/transfer.ts` are deleted. Both `prepareTransfer`s refuse a non-integer amount, and the AO one a recipient that isn't a 32-byte id (#196). `handlers/approval.ts` checks a dApp's built bytes the same way before keyfile signing.
- **Page boundary.** The page handlers move to `handlers/provider.ts`, which receives `requestApproval` only for methods marked `approval: true` in `dispatch/methods.ts`; dependency-cruiser keeps the approval handler out of its reach. `create-runtime.ts` decodes page params only after the grant, permission and wallet checks (`b0b81054`). The content script drops a `providerEvent` whose origin is not its own, and the mobile bridge posts it with the origin as target (`7dc42485`, GHSA-9cfg-49p2-8j4g). `handlers/provider-params.ts` keeps the same schemas; refusals are wrapped in `dappError`.
- **Previews.** `core/ao/other-tags.ts` (new) counts the tags a preview headline didn't read, shown beside the headline. A device token transfer of 1 shows as the token unless the preview named that collectible (GHSA-wwv3-54xq-jp3v). A text payload's preview stores only its start (`3891c818`).
- **Keys and unlock.** `handlers/key-session.ts`: cached wallet ids go through `updateStored`; the session lock uses `createSerializer` (`core/models/serialize.ts`, new). A key the keyring refuses no longer blocks other wallets (GHSA-fppj-m6cq-95vg, `handlers/wallet-lifecycle.ts`). `handlers/passkey.ts` drops the enrolment only on the vault's wrong-password error (#195).
- **Storage writes.** `runtime/src/storage-update.ts` (new) runs one read-modify-write per key at a time; `transfer.ts`, `reads.ts`, `points.ts`, `site-wallet.ts`, `peers.ts`, `announcements.ts` and `wallet-lifecycle.ts` route through it. Shared keys move to `storage-keys.ts`. `runtime/src/device-key-store.ts` takes the IndexedDB device key store (points only) out of core.
- **Network.** `core/models/network.ts`: optional `bundlerUrl` (popup-only setting, https, host granted before use) and `trimTrailingSlashes`. `core/arweave/bundler.ts` posts to `<bundler>/tx` keeping the bundler's path. Every dApp data dispatch goes to the bundler (`a78b6523`). The peers refresh found no new nodes.
- **Release and build.** `scripts/pack-release.sh` signs the attested CI zip after checking the tag signature, manifest hash, manifest commit and `gh attestation verify`, and runs no npm code. `scripts/check-bundles.mjs` (new) allowlists the npm packages in every built page and keeps the keyring page to key code. `security/surface.txt` is computed from the entry points' imports (`scripts/surface-check.mjs`), with exemptions in `surface-exempt.txt`. `.dependency-cruiser.cjs` gains the fences above. `apps/extension/build-plugins.ts`, `wxt.config.ts`, `lefthook.yml`, `pnpm-workspace.yaml` and the lockfile follow (dependency bumps #184, #188, #202).
- **UI on the surface.** `formatWinston.ts`, `MemorableAddress.tsx`, `adapters/windows.ts`, `mobile/src/adapters/storage.ts`, `apps/mobile/scripts/{bundle-hash,verify-bundle}.mjs`: small changes, no signing or key path. The last two commits (plural "bytes", releasing pointer focus when the window blurs) are outside the surface.

Outside the surface: `apps/points-api` (price cache, scan coverage and rewards), `scripts/scan`, the site, CI workflows, skills and docs.

Run:

- `pnpm vitest run`, tsc on all twelve projects, eslint, `pnpm deps:check`, `pnpm wxt:build`, `pnpm check:bundles`, `pnpm mobile:build`, `pnpm test:smoke`, and a manual check in Chrome and on a phone, including keyfile AR, AO and collectible sends through the new prepare-check-sign path.
